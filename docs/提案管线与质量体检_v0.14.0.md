# v0.14.0 交付规格：全局提案管线 + 规则中心一期 + 行内质量体检

对应 `ROADMAP.md` 的 v0.14.0 主题。三个需求组互相咬合：B 提供规则，C 在编辑工作台消费规则产出问题，问题的修复统一走 A 的提案管线落变更记录。

> 排期说明：本组原按 v0.13 起草；因动态工作流引擎底座（另一会话拍板，见 `polarion-workflow-engine` 决策）占用 v0.13，顺延至 v0.14，并增补与工作流的集成点（A1/A3）。

## 背景与目标

- 现有批准模式（请求批准 / 自动批准 / 完全访问，`apps/host/permission-policy.ts`）只覆盖会话内 agent 工具调用，且确认结果不进变更记录。
- 需求文本质量（弱词、非原子、术语不一致）目前完全靠人肉把关，工具零支撑。
- v0.13 落地的工作流顺序流自带「暂停门」，但暂停确认与 agent 审批是两套逻辑。
- 本版把「需要批准的写操作」统一为 proposal 对象（来源覆盖 agent / lint / 工作流 / 手动），并让 lint 修复成为第一个非会话来源的写入方，验证管线的通用性。

**本版明确不做**（后续版本）：整册体检报告与门禁拦截（v0.18）、语义索引/查重/影响卡（v0.16）、事件总线/收件箱/守望者（v0.17）、宏录制与定时（工作流引擎线自带，v0.15+）、跨来源全局提案队列 UI（本版提案在产生处就地审批）。

## 需求组 A：S3 全局提案管线

- **A1 提案数据结构**：`packages/protocol` 新增 Proposal 类型：`{ id, source: 'agent' | 'lint' | 'workflow' | 'manual', target: { projectId, document, workItemId? }, summary, diffPreview, status: 'pending' | 'approved' | 'rejected' | 'applied' | 'failed', createdAt, appliedAt? }`。diffPreview 复用现有 text-diff/change-diff 的结构。
- **A2 Host 提案存取**：新增 `apps/host/proposals.ts`：create / list / approve / reject / apply。apply 走现有原子写路径（block-ops / replace-all / 草稿保存通道），失败落 `failed` 并保留现场。
- **A3 会话与工作流审批统一**：agent 在 ask 模式下的工具确认、工作流的暂停门与步骤写操作，底层改为产生并裁决 Proposal 对象；现有三档权限模式行为与 UI 不变，仅数据层统一。
- **A4 变更记录打通**：applied 提案在变更记录的元数据注释中增加 `source` 字段（agent / lint / workflow / manual），变更管理时间线可见「来自助手 / 来自体检修复 / 来自工作流 / 手动」来源标记。
- **A5 验收要点**：三档权限模式回归不变；一次 ask 模式批准写操作后，变更记录里能查到带 source 的记录；lint 修复（见 C3）与工作流暂停门走同一结构。

## 需求组 B：S6 规则中心一期（规则即数据）

- **B1 配置工作项**：沿用 PSB-FEISHU 模式建 `PSB-RULES` 项目工作项，附件存规则包 JSON：`{ version, glossary: [{ term, aliases: string[], forbidden?: boolean }], lintRules: [{ id, severity: 'info' | 'warn', type, words?: string[], message, enabled }] }`。无该工作项或解析失败时回退内置默认包并在设置页提示。
- **B2 Host 规则服务**：新增 `apps/host/rules.ts`：加载附件、ajv 校验、内存缓存；扩展侧通过 RPC `rules.get` 拉取；附件更新后可手动刷新（自动刷新随 v0.17 事件总线）。
- **B3 内置默认规则包**（第一版约 12 条，全部纯文本启发式，不依赖 AI）：
  - 弱词/模糊词：快速、及时、可靠、用户友好、友好、高效、合适、若干、等等、适当的；
  - 非原子启发：同一条目内出现 ≥2 个「应/应当/须」且无分号或编号切分；
  - 指代不明：上述、如前所述、以上要求、该功能（无先行词近邻时）；
  - 无验证准则启发：条目含「应」但全文无数量/时限/状态词（阈值、以内、不超过、之前、之后、±、%、ms、s）。
- **B4 术语表**：标准词 + 别名/禁用词映射（例：`term: 刹车助力, aliases: [制动助力, BrakeBoost]`）；检测按最长匹配优先，命中 alias 标注建议替换为 term。
- **B5 验收要点**：改 PSB-RULES 附件 → 刷新后编辑工作台规则即时变化；非法 JSON 不崩、回退默认并提示；规则包带版本号，设置页可见当前版本。

## 需求组 C：编辑工作台行内体检

- **C1 lint 引擎**：新增 `packages/core/requirement-lint.ts`（纯函数，`node --test` 可测）：输入条目 HTML/纯文本 + 规则包，输出 `issues: [{ ruleId, severity, matchedText, message, suggestion? }]`。HTML→文本复用现有 polarion-html/editor-text 通道。
- **C2 行内高亮与悬停卡**：编辑工作台（DraftEditor 一侧）对命中片段加下划式高亮（warn/info 两档视觉，贴现有深林绿令牌体系）；悬停浮出解释卡：规则名 + 说明 +（术语类）建议替换词。**新浮窗不得挤占已有浮窗**（格式属性、表格快捷菜单、@引用），悬停语义遵循既有约定。
- **C3 一键修复走提案**：解释卡上提供修复动作——术语替换类直接生成 diff 预览（左右并排、逐字 diff，遵循变更对比硬性规则），确认后按 A2 apply 原子应用并落变更记录（source=lint）；句式改写类按钮「AI 改写」把条目上下文发给会话，走 agent 提案（source=agent）。
- **C4 工作台轻量汇总**：工作台头部徽章显示当前条目/本章问题数（如「体检 3 处提示」），点击滚动到下一处；**不阻塞编辑、不弹模态**（门禁拦截在 v0.18）。
- **C5 设置页规则管理**：SettingsPanel 新增「质量规则」区：查看当前规则包与术语表、从 PSB-RULES 手动刷新、恢复内置默认（仅本地回退，不改工作项）、跳转 PSB-RULES 工作项链接。
- **C6 验收要点**：真实 Polarion 文档打开后，含弱词条目可见高亮；悬停卡信息完整；术语修复从预览→应用→自动保存→变更记录可查全链路在真实浏览器亲手走通（DOM 存在 ≠ 可用）；关闭规则包后高亮全部消失、无残留样式。

## 整体验收门槛

1. `npm test`（core + host + extension/lib 三段）全绿，新增三个测试文件覆盖 lint 规则、规则包校验、提案状态机。
2. `npm run check:host` 与 `npm run check:extension` 通过。
3. 真实环境全功能自检：A5/B5/C6 全部亲手操作走通；现有功能（编辑、变更管理、飞书、会话、v0.13 工作流）无回归。
4. 干净安装验证（独立目录构建 exe 流程，注意安装包占用需重启 explorer 的既有坑）。
5. README 全量更新 + 本文档补充实际截图位。

## 风险与既有经验对照

- 悬停卡与 @ 引用 / 变更卡悬停预览的语义冲突：遵循已定的点击/悬停最终语义，同区不叠两卡。
- esbuild 产物中文 grep 陷阱：验证高亮文案时直接搜源文件而非 dist。
- Host 新命令（RPC）需重建重启 Host；旧 detached 进程可能杀不掉，沿用 invalid_union 判别法排查。
- 扩展重载需新开页面并双刷新。
- 与工作流引擎线（v0.13 起在同仓库推进）的文件边界：proposals.ts/rules.ts 为本组新增，不改动 engine.ts 既有 pump 逻辑，集成点仅限暂停门裁决处回调。
