# v0.2.6 大文档保存修复

2026-11-03（Asia/Shanghai）。本次修复已部署到本机扩展与 Host。

## 根因

现场运行的扩展与 Host 均为 0.2.5，问题不是未安装更新。原生保存按钮禁用、没有原生 input 事件，但状态检查仍返回 unknown，导致请求在真正写入前被拒绝。

真实 LiveDoc 含 605 个工作项节点。滚动后，7 个工作项由 `name="wi-placeholder" contenteditable="false"` 占位符变为完整正文，另有 4 个标题的原生图标容器消失。这些正常懒加载变化使整页 DOM 与初始指纹不同。旧版仅覆盖悬停、光标和图片属性等装饰变化，未覆盖该大文档加载方式。

## 修复边界

- 仅当原生保存按钮明确禁用、未捕获原生输入时，接受同 ID 的占位符加载成具有原生起止字段容器的工作项。
- 完整对比剩余文档：已有正文、样式、工作项顺序及段间文字必须保持一致，不能借懒加载重新建立整页基线而掩盖真实编辑。
- 加载完成的工作项进入新的基线，后续正文或格式变化仍被检测。
- 忽略观察到的原生图标容器变化；服务端版本冲突和保存后独立回读保持执行。

## 验证

1. 新增 6 项回归用例；全部 85 项测试通过，Host/Extension 类型检查与构建通过。
2. 回放实际大文档的初始和当前 HTML，状态由 unknown 变为 clean。
3. 本机扩展重载并刷新正式大文档后，滚动到 SVWT-650，打开用户既有 revision 1 草稿，通过界面点击“保存到 Polarion”。
4. 保存审计为 verified；新建独立连接回读，服务端 description 与保存后的草稿逐字一致，且不同于原始正文。草稿状态为 clean。
5. 服务端更新时间为 2026-11-03T08:11:23.706Z（北京时间 16:11:23）；HTML SHA-256 为 `8613f750aa1ae11974232c6b1be2993477b8e6b996917759ad4658b8fcb4e869`。
6. 原生页面显示更新后的标题、判定说明和列表；K=0.3、阈值 [15,32]、信号名、红色交叉引用及属性区域仍在。原生编辑器将 HTML 标题渲染为带字号的 span/br，本次没有将其误判为远端数据丢失。

验证过程中曾遇到 Polarion 静态资源返回 503，重新读取恢复后才继续。没有通过关闭原生状态检查绕过问题，也没有修改其他待保存草稿。
