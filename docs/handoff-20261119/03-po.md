## 4. 阻塞与下一具体动作

### 4.1 阻塞（当前唯一阻塞，也是用户最后反馈的问题）

**扩展在真实浏览器里无法加载**，报：

> 无法为内容脚本加载 "content-scripts/workbench.js" 文件。该文件采用的不是 UTF-8 编码。

已排查事实：

1. 磁盘文件全量校验通过：`spikes/extension` 208 个 js/css/json/html **全部是合法 UTF-8、无 BOM**；`workbench.js` 1,985,436 字节、md5 `805ed7a28e2793d88fee68c0095379b5`、普通文件（非符号链接）、无 NUL、连续 35 分钟未被改动。
2. 该产物由**并行画板会话**在 01:34 重新部署（比我的 01:09 版本更大），因此文件内容是对方线的代码（含 KaTeX 打包结果）。
3. 文件里含 **1 个裸 `U+FFFF`（字节 `EF BF BF`）**，来自 KaTeX 的 Unicode 区间正则：`` `([!-\\[\\]-‧‪-퟿豈-￿]` ``。Chrome 的严格校验 `IsStringUTF8` 会显式排除非字符 U+FFFE / U+FFFF——**这是最可疑的根因，但尚未证实**：
   - 用 Edge headless 二分，失败边界正好落在 `U+FFFF` 前一个字节（offset 765094 通过、765101 失败）；
   - 但把 `U+FFFF` 换成 `\uFFFF` 转义的整文件变体**依然失败 3/3**，说明要么还有第二处触发点，要么根因不是它。
4. 版本信息：用户的浏览器是 **ego (lite) 0.6.3.14，Chrome/156.0.0.0**。
5. 自动化安装受阻：ego 在 `chrome://extensions` 上**普通点击有效**（开发者模式开关可翻转），但点「加载未打包的扩展程序」**不会弹出系统文件夹选择框**（Win32 枚举无 `#32770` 窗口）；`orca` 未运行，无法用桌面自动化接管对话框。
6. 已准备 ASCII 路径快照 `C:\psb-ext-dev`（与源逐字节相同、208 文件校验通过），用于排除中文路径/并行覆盖变量——**尚未用它试装载**。
