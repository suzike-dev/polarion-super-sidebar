## 1. 最初目标（用户原话）

> 「Cloud code 或者 zcode 里不是有个动态工作流这个功能吗？咱们这个工具能引入动态工作流这个功能吗？这样是不是我就可以去编排定义一些特定的工作流，后期不断地重复使用这个工作流，我举个简单的例子，比如针对某一个需求，我定一套工作流：先让 AI 去审核需求，然后再去看模型，看完模型以后，再给什么东西。」

> 「当然，这样的需求可能非常多，能不能去自定义这种动态工作流，并不断去复用自定义好的工作流？」

即：把「需求评审 → 模型核对 → 出结论」这类多步流程定义成**可保存、可反复运行**的工作流，而不是每次重新描述。

我给出了设计说明（Host 侧编排器 + 每步一条普通 run + 斜杠触发 + 本机存储），并提两个选择题；用户答复：

## 2. 追加 / 删改与最终目标

### 2.1 已批准（本会话按此实现）

1. **完整编排引擎**为最终形态（条件分支、每步独立上下文、并行步骤），跨多版本分批交付；**不做最小内核**。
2. **本机优先存储**：Host sqlite（`workflow-def` / `workflow-run` 两类记录），JSON 结构对齐后续 PSP 团队共享附件格式，v0.16 再一键迁移；不先做团队共享。
3. 编排器放 **Host 不放前端**；状态落库，刷新/关页/重启可恢复。
4. 诊断结论（我提出、用户以「完整引擎」选择默认采纳）：每步展开成同会话的普通 run，复用现有工具/批准模式/队列/经验沉淀，不另建执行器。

### 2.2 纯建议（未被用户明确批准，仅记录；总负责人可改）

- **分期编号与内容**：v0.13 顺序流底座 → v0.14 类型化输出+条件分支/循环 → v0.15 并行扇出+每步独立会话（新鲜视角）→ v0.16 PSB-WORKFLOWS 团队共享+批量工作项触发。其中 v0.13 已实现，其余仅写入设计文档。
- **触发语法** `/wf:名称 [补充说明]`（斜杠菜单顶部「工作流」分组）。
- **暂停语义**：pause 步完成后暂停；「继续」= 确认该步、直接进入下一步（**跳过暂停步本身**）；最后一步带 pause 按完成处理，不暂停。
- **Host 重启恢复语义**：在飞步骤被打断→实例转 `paused`（error=HOST_RESTARTED），「继续」跳过该步；未开始的实例自动续跑。
- **失败语义**：任一步非 completed → 实例 `failed`，不自动重试，由用户重新发起。
- **UI 形态**：输入框上方工作流条（running/paused/done/failed/cancelled）、会话栏 Workflow 图标入口、独立浮层管理面板（列表 + 表单编辑）。
- **对话式沉淀**：新增模型工具 `save_workflow`（用户说「把这套流程存成工作流」时由模型整理步骤保存）。
