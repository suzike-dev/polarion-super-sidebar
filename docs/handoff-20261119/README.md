## 开发顺序与完成条件

1. **恢复扩展装载**。经验线记录了 Chromium 对 `content-scripts/workbench.js` 的 UTF-8 报错，工作流线和总负责人都观察到 Ego 已安装列表缺失此扩展。磁盘上入口齐全。先在独立环境复现并验证构建修复，再操作用户的加载目录。
2. **统一工程基线**。以同一个工作树运行 Host/扩展两端类型检查、全量单测和双端构建。接手时全量 447/447 通过，两端类型检查均在 ProseMirror 节点构造和树图坐标处报错。各原会话的旧计数仅用于追溯。
3. **串行整合共享入口**。`DraftEditor` 统一验收画板插图、富文本、实现模块与质量体检。`App` 核查各浮窗互斥、斜杠和会话。协议、Host 服务和引擎同批核对命令及来源。`model.ts` 归模型关联，PO 会话在此补过测试。
4. **真实工程验收**。在测试项目、测试文档上按上表实际操作，同时核对界面可见结果与保存后重新打开的内容。执行跨功能链路：同一需求关联模型、运行评审工作流、修改草稿、放置配图、处理体检提案。最后做旧文档和基础会话的回归。
5. **版本和后续范围**。当前工作树已使用 0.13.0，富文本/模型关联和工作流原先分别占用此号。统一在发布前按实际验收功能整理一次版本说明。质量体检与提案管线按 v0.14 规格推进。追溯覆盖、查重、影响分析、收件箱、评审门禁、时间视图、证据链、仪表盘和大文档体验保留在[总路线图](../../ROADMAP.md)，具体后续排期以该路线为准。

用户要求多场景验证后再谈发布。浏览器加载、Host 联通或单项实操仍受阻时，记录具体阻塞和复测入口。相关规格见[动态工作流方案](../动态工作流引擎设计_20261119.md)和[提案与质量体检](../提案管线与质量体检_v0.14.0.md)。
