# 富文本、文档表格、图片与画板审查

日期：2026-11-03。审查版本：当前工作树 v0.2.6。产品结论：**partial**，不能声明完整替代 Polarion 原生编辑器。以下最初发现来自源码/规格核对及纯本地 jsdom/ProseMirror 实验；未操作真实业务数据。后续修复状态单独列出，测试通过不等于浏览器与 Polarion 回读验收通过。

## 范围与依据

依据 `docs/富文本与原生Agent能力补充规格_v0.2.md`、`docs/编辑工作台对标与交付规格_v0.3.md`。第一版高阶文档表格必须包含合并拆分、行列、样式和批量粘贴；公式、多视图、多工作表等为后续愿景，不按第一版 P1 处理。

源码范围为 DraftEditor、RichSurface、FormatProperties、编辑 helpers、rich schema/source mapping、画板入口及 Host 保存接口。主 Agent 的 SVWT-650 保存回读与 SVWT-538 409×268 图片实测只说明对应样本；不得外推全部图片已通过。

## 发现及状态

### ED01 · P1 · 含图片矩阵粘贴改变表结构

- 步骤/影响：将含图片的 1×2 表格粘贴到已有 1×2 首格，原通用 slice 路径生成 1×4，并把旧首格正文串入新第二格。
- 证据：`apps/extension/ui/DraftEditor.tsx` 的 importRichClipboard；`packages/core/rich-paste.ts`。原行为已用实际 ProseMirror 本地复现。
- 修复状态：**已代码修复、定向测试通过，待浏览器**。含图与 TSV 共用 `pasteRichContent`，先走表格矩阵规则，非矩阵才用通用富文本插入。
- 验收：含图/不含图矩阵同规则覆盖、扩展；图片归属正确；合并格、嵌套、撤销和保存回读完整。

### ED02 · P1 · 编辑器内部图片引用无法粘贴

- 步骤/影响：复制已有图片后粘贴；序列化得到 workitemimg:/polarion-asset:，原 HTTP(S) 检查拒绝内部协议。
- 证据：`packages/core/rich-schema.ts` RichImage、`apps/extension/ui/DraftEditor.tsx` importRichClipboard；协议拒绝已本地复现。
- 修复状态：**已代码修复、定向测试通过，待浏览器**。`packages/core/rich-clipboard.ts` 在复制时写入项目/文档/工作项归属，同项引用解析为可保存资产。**跨工作项图片复制未支持**，来源不明或跨项相对引用明确拒绝，不猜测附件归属。
- 边界：远程画板剪切后若原引用已从草稿同步删除，boards.open 的引用保护可能拒绝源 bundle；会明确失败，不降级为普通截图。完整画板剪切仍未验收。
- 验收：同项复制/剪切/粘贴、刷新、保存回读；图片字节与附件引用一致；跨项拒绝提示明确。

### ED03 · P1 · 复杂原生表格变成 protected 占位符

- 步骤/影响：含 colgroup/caption 或 thead+tbody 的表格整表不可编辑；用户新增 SPE-711 截图还显示两个“Polarion 宏 · table”占位符。
- 证据：`packages/core/rich-document.ts` 的 blocks/inline/block macro 检查及 table children 白名单。真实 SPE-711 第 3、5 张 table 的 id 为 `polarion_wiki macro name=table`，没有末尾分号；旧判断只接受 `name=table;`，误判为未知宏。git HEAD 旧解析器对同一 fixture 复现 3 个可编辑 table、2 个 protected。此真实样本的直接根因不是 class、colgroup 或多 row group；后两类另有合成回归样本。
- 状态：**已代码修复并通过真实本地 fixture 核验，待浏览器及 Polarion 回读**。macro name 按完整名称识别，支持有/无参数的 table；已知 table 宏的 span/div 包装不再走 inline 保护分支；colgroup/caption、多 row group 建立源布局映射。未知宏与无法安全解析的表格仍保护。
- 保留边界：caption/colgroup 当前保真存储，尚无专用编辑入口；跨 row group 重排会明确拒绝，以免重复带身份的分组包装或静默改变结构。class 包含 polarion 本身不是宏识别条件；识别依据为原生 id 中的 macro name。
- 验收：无编辑逐字节一致；改单格只改变目标文本；列宽、分组、caption、宏身份和其他源片段保留；真实 SPE-711 编辑视图及回读验证。

### ED04 · P1 · TSV 引号换行被拆成多行串列

- 步骤/影响：两行三列 TSV 内一个单元格含引号包围换行，原 split 实现拆成三行，引号残留并改变列对应。
- 证据：DraftEditor 的 TSV 分支；已本地复现。
- 修复状态：**已代码修复、定向测试通过，待浏览器**。`packages/core/editor-text.ts` parseTsv 支持引号、双引号转义、单元格换行/Tab、空尾格，异常引号明确拒绝；正文换行输出 br。
- 验收：前导零、单位、科学计数、引号、换行与空尾格保持原值和区域，保存回读一致。

### ED05 · P1 · 正文附件/工程引用及原生宏编辑缺失

- 步骤/影响：在需求中插入本地 PDF、已有工作项/文档附件、工作项引用，或编辑已有引用宏，没有完整工作台入口。
- 证据：DraftEditor 文件选择仅接受图片，插入区没有正文附件/引用选择器；rich-document 将宏设为 protected。引用宏模型已本地复现。
- 状态：**缺失/仅保留**。AI 上下文附件不能代替正文附件。
- 修复/验收：增加正文附件与已有附件浏览器、引用和支持宏适配；在工作台完成创建、修改、删除，并验证附件归属、链接、身份和回读。

### ED06 · P2 · CSS 图片尺寸/对齐未应用到编辑 NodeView

- 步骤/影响：仅 style 指定 409×268 和居中的图片，模型 width/height 为 null、align 为 left；NodeView 未使用 sourceStyle。
- 证据：rich-document.inline image 读取 HTML 属性；`apps/extension/lib/editor-images.ts` paint。模型已本地确认，实际视觉待浏览器。
- 状态：**未修复/浏览器未验证**。
- 修复/验收：统一属性与 CSS 尺寸解析、单位与优先级；编辑、阅读、原生三端尺寸比例对齐一致。

### ED07 · P2 · 查找不跨格式，空替换写空格

- 步骤/影响：“温度”与加粗“阈值”可见连续却搜不到“温度阈值”；替换为空产生空格。
- 证据：DraftEditor.findNext 原逐 text node 搜索与 replace || ' '；0 命中已本地复现。
- 修复状态：**已代码修复、定向测试通过，待浏览器**。findTextMatches 跨格式边界，段落/内联对象仍为边界；replaceSelectedMatch 空替换真删除。
- 验收：跨粗体/颜色/链接查找、位置跳转、空替换、保留周边格式与撤销。

### ED08 · P2 · 列表起始编号/续编与任务列表入口缺失
