# Polarion 账号设置验收（2026-11-04）

0.4.0 将账号密码配置放入设置。用户输入后点击“保存并连接”，先登录 Polarion，成功后替换本工具的加密凭据并切换 Worker；不要求执行配置命令或重启 Host。

## 已验证

- Windows 本机完整类型检查、自动测试 **202/202**、Host 和扩展构建通过。
- 新增 Host 测试通过真实 PowerShell/DPAPI 检查输入管道、加密文件、失败保留旧配置、成功替换、临时文件清理与 Worker 切换。该测试中的登录成功/失败由测试替身控制，不算真实认证证据。
- 真实 Ego 0.6.2.7 / Polarion 页面使用已配置的同一账号完成表单输入、点击“保存并连接”，显示连接成功；密码框提交后清空。凭据仅在本地进程内转交，未写入脚本、命令参数、测试输出或截图。
- 真实页面打开悬浮工作台，实际载入 `SPE-565` 的正文和表格，未触发 Worker stopped。仅打开与读取，没有修改或保存服务器需求。
- 使用随机、不存在的测试用户名做一次真实失败登录：页面显示账号或密码不被接受；保存前后有效凭据文件的 SHA-256 相同；随后“检查已保存的连接”成功。
- 诊断页面显示扩展与 Host 均为 **0.4.0**，实际 Host PID 为 32208。设置成功后不依赖 Host 重启；为部署新代码执行的 Host 重载发生在表单验收之前。
- UI 运行测试覆盖遮蔽密码、提交后清空、等待期间禁止重复提交、失败反馈和成功状态。Worker 启动测试覆盖文件缺失、文件不完整、版本不支持、解密失败和后续重试。

## 数据与兼容性

密码由 Windows CurrentUser DPAPI 加密，仅当前用户/System 有文件访问权。写入候选文件后先验证认证，再以同目录 rename 替换最终文件；登录失败删除候选文件并保留原文件。密码不进入 SQLite 设置、AI 会话或命令行参数。

显式安装凭据路径仍生效；没有显式路径时，界面写入本工具私有 `credentials.json`，不会覆盖旧 MCP 兼容兜底文件。旧 MCP 和终端令牌配置仍可读取；界面仅提供账号密码配置。成功认证不代表账号具备所有项目的读写权限。

## 验证边界

本次为当前 Windows 用户与真实公司 Polarion 实例的验收，不是第二台电脑、全新 Windows 用户、全部浏览器或所有项目权限的验收。跨电脑应由对方在自己的设置中输入账号密码；不迁移本机 DPAPI 文件。未扩大正文写回和富文本兼容性结论。
