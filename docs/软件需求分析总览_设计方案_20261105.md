# 软件需求分析总览 · 前端设计方案与交互细节

> 版本：v1（2026-11-05）｜验证文档：`45_SPE25_BQ1_TM_002 / Design / Software Requirement Specification SWR`
> 真实规模：**456 个工作项 / 6 个二级章节 / 25 个三级分组 / 最深 6 级**

---

## 1. 定位与边界（关键决策）

| 项 | 结论 | 理由 |
|---|---|---|
| 功能归属 | **侧边栏主工具内的一个视图**，不是独立工具 | 属于「工程助手」能力，复用其数据链路、权限、会话 |
| 入口 | 侧边栏头部**唯一一个**「总览」按钮 | 不新增第二个入口，不与设置/收起冲突 |
| 展示位置 | 点击后在**左侧文档区**展开总览面板（不是侧边栏内，也不是全屏新窗口） | 侧边栏仅 340–420px，无法承载矩阵；左侧文档区约 900–1200px，可容纳 3 列 |
| 与对话关系 | 并存。总览展开时侧边栏对话保持可用 | 用户常需「看总览 → 追问 AI」，不能互斥 |
| 预览与编辑 | **完全复用现有 `WorkItemReader`**（`workitems.read` + `onOpenEditor`） | 已有能力：正文渲染、图片、表格、Esc 关闭、一键进编辑工作台 |

## 2. 真实数据的结构结论（决定 IA）

对 `SWR` 文档实测：

```
1 变更履历(1) | 2 目录(1) | 3 项目介绍(10) | 4 ASW软件功能需求(425) | 5 BSW功能需求(16) | 6 非功能需求(3)
4.1 整车状态识别(24) 4.2 传感器处理(34) 4.3 空调功能(82)
4.4 热管理功能(85)  4.5 热系统控制(93) 4.6 负载控制(106)
```

- **425/456 集中在第 4 章**，层级深达 6 级（`4.3.10.x`）。
- 199 条是 `heading`（章节标题），257 条是 `softwarerequirement`（真实需求）。
- Polarion 本身已有目录树；再复制一棵树不解决问题——**低效正是"逐层点开"造成的**。

**最终 IA：二级目录做色带、三级目录做块、条目平铺其中，不做可折叠树。**
- 二级目录（章）＝一条横向色带，颜色即区块身份，用于快速定位"在哪一片"。
- 三级目录（组）＝色带内的块，**块宽按条数加权**（√n），大组自然占更宽，形成"块度"。
- 条目＝块内单行小格，**只显示 `SPE-xxx` + 工作项名称**，无状态字、无路径、无计数。
- 层级不再需要点击：全部默认可见，靠颜色与块宽辨认，靠搜索收敛。

### 3.2 侧边栏（仅一个按钮）

在协作栏/头部追加：

```tsx
<button className="sv-trigger" onClick={toggleOverview}>
  <LayoutGrid size={13}/> 总览
```

## 4. 交互规格

| 交互 | 行为 | 实现要点 |
|---|---|---|
| 点条目格 | 打开现有阅读预览 | `rpc('workitems.read')` → `WorkItemReader`（含「编辑正文」→ `openDraft`） |
| 搜索输入 | 即时过滤：非命中格 `display:none` | 命中 ID/名称高亮；**变空的分组块与章节带一并隐藏**，并按可见条数重算块宽 |
| Ctrl/Cmd+F、`/` | 聚焦搜索并全选 | 阻止浏览器默认查找 |
| Esc | 依次：关预览 → 清搜索 | 两级栈 |
| 关闭 | 面板收起，侧边栏按钮回未激活态 | 文档区恢复原文 |

### 状态与空态

- **加载中**：骨架（3 条色带 × 若干灰格），不显示「0 项」。
- **失败**：面板内错误条 `读取文档结构失败 · 重试`，保留搜索框。
- **空文档**：居中提示「该文档暂无工作项」。
- **超大文档**（>1500 项）：分组级分批渲染（先渲染前 20 组，滚动追加），过滤在数据层做。
| Ctrl/Cmd+F | 聚焦搜索框并全选 | 阻止浏览器默认查找 |
| Esc | 依次：关预览 → 清搜索 → 收面板 | 三级栈，不越级关闭 |
| 展开全部 / 折叠 | 全层级一次开合 | 图标按钮（`unfold/fold-vertical`），工具提示 |
| 关闭 | 面板收起，侧边栏按钮回到未激活态 | 文档区恢复原文 |

### 状态与空态

- **加载中**：骨架卡片（3 列 × 6 张灰块），不显示「0 项」。
- **失败**：面板内错误条 `读取文档结构失败 · 重试`，保留搜索框。
- **空文档**：居中提示「该文档暂无工作项」+ 文档链接。
- **超大规模**（>1500 项）：先只渲染章节 + 分组，工作项行按展开惰性渲染（避免首屏 4k DOM）。

## 5. 视觉规范（与现有工具一致）

复用侧边栏既有令牌，不引入新色系：

| 用途 | 值 |
|---|---|
| 主色 / 深主色 | `#356C7C` / `#2D5E6C` |
| 画布 / 卡片 | `#F4F5F3` / `#FFFFFF` |
| 主文字 / 次 / 三级 | `#1F2A31` / `#586A72` / `#7A8A91` |
| 分割线 | `#DBE3E7` / `#E9EFF2` |
| 状态色 | open `#64748B`｜draft `#B97F1F`｜reviewed `#3572C7`｜done `#2E9E6B` |
| 圆角 | 卡片 9px、行 5px、胶囊 999px |
| 字阶 | 章节 12px/600，分组 11.5px/500，工作项 11.5px，ID 9px 等宽 |

**克制的高级感**（本轮明确不要深空/霓虹）：
- 面板入场 300ms 上浮 12px；卡片 stagger 45ms。
- 章节卡左侧 2.5px 色带 + 顶栏下方极淡径向渐变（不走玻璃拟态，保证文字锐利）。
- 行 hover：底色 `#F0F6F8` + 1px 描边，不做位移与发光。
- 全程 `prefers-reduced-motion` 关闭动画。

## 6. 数据链路（已实现）

```
点总览
  → rpc { method: 'document.outline', target }
  → apps/host/service.ts  case 'document.outline'
  → apps/host/polarion.ts Polarion.outline()          → worker 子进程
  → apps/host/polarion-worker.ts  method 'outline'
  → soap.getDocumentWorkItems(projectId, location, ['id','title','status','type','outlineNumber'])
     （字段集按需降级：失败时依次退到 ['id','title','outlineNumber'] → ['id','title']）
  → { documentId, title, items:[{id,title,status,type,outline}] }
  → 前端 buildOutlineChapters() 按 outline 还原 章 → 分组 → 条目
点条目
  → 复用现有 openReader(workItemId)（workitems.read → WorkItemReader → 编辑正文）
```

改动清单：

| 文件 | 改动 |
|---|---|
| `packages/protocol/index.ts` | 新增命令 `document.outline`；导出 `DocumentOutline` / `DocumentOutlineItem` |
| `apps/host/polarion-worker.ts` | 新增 `outline` 分支，字段集降级重试，失败归一为 `DOCUMENT_OUTLINE_FAILED` |
| `apps/host/polarion.ts` | `Remote.outline?()` + `Polarion.outline()` |
| `apps/host/service.ts` | `case 'document.outline'`，未连 Polarion 时返回 `POLARION_UNAVAILABLE` |
| `apps/extension/lib/document-outline.ts` | 新增：纯函数 `buildOutlineChapters` / `filterOutlineChapters` / `countOutlineItems` |
| `apps/extension/lib/document-outline.test.ts` | 新增 6 条单测（分组、未编号归置、过滤、排序、色相） |
| `apps/extension/ui/RequirementsOverview.tsx` | 新增总览面板组件 |
| `apps/extension/ui/requirements-overview.css` | 新增样式（章节色带 / 加权分组块 / 单行条目） |
| `apps/extension/ui/App.tsx` | `overview` 状态；两处头部各一个按钮；渲染面板并在关闭时回退 |

### 生效步骤（本机开发环境）

1. `npm run build:host` 后**重启本地 Host**（worker 子进程是长驻的，旧进程仍持旧代码）。
2. `npm run build:extension` → `scripts/deploy-dev-extension.ps1` 同步到 `spikes/extension`。
3. `chrome://extensions` 重载扩展，然后在 Polarion 文档页**新开或刷新页面**。

## 8. 已知取舍

1. **不做目录树**：Polarion 已有目录树，低效来自逐层点开；总览的价值是"平铺 + 过滤"。
2. **不做统计图形**：用户目标是"扫到某条需求"，不是看谁最多；面积/热力图属于另一种阅读任务。
3. **heading 不进卡片墙**：199 条章节标题不是需求，混入会稀释信噪比；章节信息压缩为卡片上的分组号。
4. **全部常驻 DOM**：258 张卡片一次性渲染，过滤只切 `.hide`，避免重排与滚动位置跳动；超 1500 项时改分批。
