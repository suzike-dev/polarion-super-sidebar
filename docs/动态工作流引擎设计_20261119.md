# 动态工作流引擎 · 设计方案（2026-11-19）

## 背景与决策

用户需要把日常重复的多步 AI 流程（例：需求质量评审 → 模型一致性核对 → 生成评审意见）定义成**可复用的工作流**，一键对当前工作项重复执行。参照 ZCode dynamic-workflows 的「定义 → 执行器 → 保存复用」理念，但不抄其脚本语言与子代理拓扑——本产品的场景是**领域提示词步骤链**，表单化顺序步骤覆盖绝大部分需求。

已拍板：

- **范围 = 完整编排引擎**：最终形态含条件分支、每步独立上下文、并行步骤；跨多版本分批交付。
- **存储 = 本机优先**：Host sqlite 记录（kind：`workflow-def` / `workflow-run`），定义 JSON 结构与后续 PSB-WORKFLOWS 附件格式对齐（复用 PSB-FEISHU 的 gzip + 乐观并发模式），后续加「发布为团队共享」一键迁移。

## 总体架构

```
UI（App.tsx / WorkflowPanel）
  /wf:名称 斜杠触发 · 工作流条（进度/暂停/继续/终止）· 管理面板
    → rpc workflows.run / resume / cancel / list / save / delete
    → Host Workflows 编排器（apps/host/workflows.ts，状态机落 sqlite）
      → 每步展开成一条普通 run（复用 startRun / 队列 / 工具 / 批准模式 / 经验沉淀）
      → 挂在 Engines.pump() 的会话空闲点上推进
```

关键决策：

1. **编排器放 Host 不放前端**：状态落库，页面刷新/关页不丢；与现有 pump/队列机制天然衔接。
2. **每步 = 一条普通 run**：同会话连续执行，模型天然看到历史轮次；工具、批准模式、@ 引用、经验沉淀全部免费继承。「看模型」等步骤直接用会话里挂的 simulink/polarion 工具。
3. **逐条发送而非整链排队**：绕开 `MAX_QUEUED_RUNS=5`；用户中途插话时，排队消息按 FIFO 先于下一步工作流步骤执行；暂停点自然成立。
4. **运行实例快照定义**：WorkflowRun 启动时快照 steps，之后编辑定义不影响在跑实例。

## 数据模型（packages/protocol）

```ts
WorkflowStep = {
  id: slug;              // 步骤标识，模板引用 {{steps.<id>}}
  title: string;         // 步骤名（用户语言）
  prompt: string;        // 提示词模板，支持 {{item}} {{prev}} {{steps.<id>}}
  guidelineId?: uuid;    // 该步附加指令
  pause?: boolean;       // 完成后暂停，人工确认再继续
}
WorkflowDef = { id, projectId, name, description, steps[1..30], createdAt, updatedAt }
WorkflowRun = {
  id, defId, defName, sessionId, target（冻结）, contexts（冻结）, permissionMode, note?,
  status: 'running' | 'paused' | 'done' | 'failed' | 'cancelled',
  currentIndex,          // 不变式：下一个要执行的步骤下标（暂停时指向已完成步骤）
  steps: [{ stepId, runId?, status, resultTail? }],
  def: { name, steps }（快照）, startedAt, updatedAt, endedAt?, error?
}
Run.workflow? = { workflowRunId, defName, stepIndex, stepTotal, stepTitle }   // 步骤徽标数据
```

命令：`workflows.list/save/delete/run/resume/cancel`；`sessions.read` 回包增加 `workflow?: WorkflowRunView`（当前会话最新工作流实例视图，重字段剥离）。

## 执行状态机（v0.13 顺序流）

```
workflows.run ──► 校验（项目匹配/会话无进行中工作流/名称唯一）
  ──► 建 WorkflowRun（running, currentIndex=0）──► advance()
advance(sessionId)（由 Engines.pump 每次会话空闲时调用，同步无 await）：
  1. 无 running 实例 → 返回
  2. 会话有在飞 run → 返回（队列先走；它们结束后 pump 会再调 advance）
  3. 当前步 runId 在飞 → 标记 running，返回
  4. 当前步 run 终态 → 收割：result 事件尾部 4000 字存 resultTail；步骤状态映射
     - 非 completed → 实例 failed（v0.13 不自动重试，UI 可重新发起）
     - 最后一步 done → 实例 done
     - pause 步 done → 实例 paused（等 UI 继续/终止）
     - 否则 currentIndex++ → 启动下一步
  5. 当前步未启动 → 组装提示词（头行 + 变量插值 + 补充说明）→ startRun → execute/入队
resume：paused → running，currentIndex++（跳过暂停确认步）→ advance
cancel：当前步在飞则 engines.cancel；实例置 cancelled
recover（Host 启动）：当前步 run 已 completed → 自动续跑；否则置 paused（HOST_RESTARTED），用户决定
```

提示词组装（进模型的实际文本）：

```
【工作流「需求三连审」步骤 2/3：模型一致性核对】
（本条消息由用户保存的工作流自动发出，属于既定流程的一步；完成后将自动继续。）
<插值后的步骤提示词>（{{item}}→当前工作项、{{prev}}→上一步 resultTail、{{steps.<id>}}→指定步）
（用户本次运行的补充说明：…）   ← 仅当触发时带附注
```

## UI（v0.13）

- **触发**：composer 输入 `/` → 斜杠菜单顶部「工作流」分组（与原生命令统一键盘导航）；选中填入 `/wf:名称 `，可尾随补充说明，Enter 触发。管理面板里也可直接运行。
- **工作流条**：输入框上方（与队列条同区）：running 显示「工作流「名」· 步骤 i/total · 标题」+ 终止；paused 显示继续/终止；done/failed 短暂显示结果（5 分钟窗口，可手动关闭）。
- **步骤可读性**：每步消息的 user 文本自带【工作流「名」步骤 i/total：标题】头行，历史回放同样可读；排队条显示同文。
- **管理面板**：session-bar 新增工作流入口（独立浮层，不挤占已有浮层）：列表（名称/描述/步骤数）+ 表单编辑（步骤标题、提示词、附加指令、暂停开关、增删排序）+ 新建/删除（两步确认）/运行。
- **对话式沉淀**：新增 `save_workflow` 模型工具——用户说「把这套流程存成工作流」，模型总结出步骤并保存（名称冲突报错引导改名）。

演进不加迁移负担：定义/实例都是 JSON 记录 + zod 默认值解析，新字段向前兼容。

## 测试与验收要点

- 单测（apps/host/workflows.test.ts，fake query 工厂）：顺序两步自动接力且 `{{prev}}` 注入上一步结果；暂停 → resume 续跑；步骤失败 → 实例 failed；用户插队消息先于下一步；名称冲突。
- 真实浏览器验收（发布门槛）：斜杠菜单选工作流 → 触发 → 步骤头行可见 → 暂停条出现 → 继续 → 完成；中途插话顺序正确；Host 重启后实例转暂停；管理面板增删改排序；save_workflow 对话沉淀可用。
