## 3. 连线吸附修复（用户反馈 · 2026-11-05）

**现象**：素材（如方/圆形工程符号）之间连线时无法自动吸附。

**根因**：Excalidraw 的箭头绑定只支持 `rectangle/diamond/ellipse/text/image/frame` 类型；素材符号大量使用 line 绘制（三通阀、换热器、膨胀阀等），线条元素永远不能成为绑定目标；即便含矩形/椭圆子件，也必须精确悬停到那个子形状上才可能命中。

**修复**：`Artwork.finish()` 为每个单体素材在 z 底层生成一块覆盖全范围（含 4px 边距）的白色绑定壳（`type:rectangle`、白底、透明描边、宽 0、`customData.role='bind-shell'`、与素材同组）。白色填充使素材内部任意位置的指针命中都落在壳上，箭头起终点靠近素材即吸附；移动素材时连线跟随。泳道框架（纵/横/网格）与六个整图模板不加壳——这些场景连线应绑定内部节点而非外框。

**不变量**：结构测试强制非豁免素材的第一个元素必须是覆盖全部图形的绑定壳（类型/颜色/组/覆盖范围逐项断言）；豁免清单 `BOARD_LIBRARY_SHELL_EXEMPT` 导出供测试对齐。

**存量数据升级（2026-11-05 补充修复）**：真实测试发现旧安装（无壳版本）因为 `installedBuiltinIds` 安装账本不会自动升级——用户升级后依旧拿不到吸附。已新增 `upgradeBuiltinShells()`：打开画板时对已安装的内置素材只补缺失的绑定壳，保留用户改名/修改、不复活已删除项、不重复加壳；`load()` 仅在确有变化时回写。新增测试覆盖（升级、幂等、墓碑、编辑保留）。真实存储验证：升级前 71 项中 25 项带壳 → 打开画板后 61 项带壳，未带壳的 9 项正好是豁免清单（3 泳道框架 + 6 整图模板）。

**存量数据边界**：素材 ID 是安装身份，用户已保存的旧素材不会自动重绘（含已删除墓碑）。绑定壳同属素材组，解组后可单独删除。

**边界**：使用「直线」工具（快捷键 6）绘制的线**永远不参与绑定**（Excalidraw 原生设计，端点圆点只是编辑点）；吸附只作用于箭头工具（快捷键 5）。绑定壳对画布白底不可见，若用户手动改画布背景色，壳区域会显示为白色。

**交互可发现性（2026-11-05 补充）**：Excalidraw 没有飞书那种常驻锚点圆点，吸附反馈是「端点拖入形状 → 形状描边高亮 → 松开」。为消除误解，画板新增底部提示条：选中直线时提示“直线不参与吸附，请用箭头工具（快捷键 5）”；箭头工具激活时提示“把端点拖进形状内部，形状高亮时松开即完成连接；之后拖动形状，连线会自动跟随”。

**实测取证（磁盘源文件，非截图推断）**：

1. 素材吸附：插入膨胀阀（纯线条绘制）后在正文草稿生成的源 JSON 中，箭头 `startBinding.elementId` 精确等于该素材的绑定壳 id（`customData.role='bind-shell'`），间隙 8px。
2. 拖动跟随：两个矩形用箭头连接后拖动 A（+150,+70），源 JSON 显示 `startBinding/endBinding` 均保持，箭头绝对起点距 A 右缘 6.79px、终点距 B 左缘 6.79px（均在 8px 吸附间隙内）。
3. 原生矩形互连：箭头两端分别绑定两个矩形，证明画板内绑定机制本身正常，问题只在“素材符号是线条、无法成为绑定目标”。

## 4.1 时序图生成（2026-11-05）

**能力**：`kind=sequence` 使用 `participants`（2–6）与 `messages`（1–14，`kind=sync|return|self`，text ≤120 字）替代 `nodes/edges`；提供 `nodes/edges` 或混用将被 schema 拒绝。

**布局**：参与者表头等距排列（表头宽 120、最小间距 88，窄画幅放不下时提示拆图）；每条生命线是宽 2px 的矩形（Excalidraw 只允许箭头绑定形状，线条不能绑定），消息箭头以 `fixedPoint` 绑定到生命线的具体高度；拖动参与者组时生命线与消息一起移动。自调用输出 4 点直角回路，`kind=return` 使用虚线；消息标签固定在箭头上方，靠近右边界时自动改为左侧放置。

**校验**：自带几何检查（生命线必须是细矩形、普通消息必须水平、自调用必须正交、标签不得压住表头、所有元素在画布内），并沿用 `checkBoardCanvas`。

**验收证据（真实浏览器 + Host 管线）**：
- 真实 Claude 通过 `read_board_generation_context(visualType=sequence)` 读取上游时序图规范，`propose_board_generation` 生成「评审请求时序图」（3 参与者、4 消息含自调用与返回），预览卡显示 3 节点 4 连线，应用后插入正文成功。
- 落盘源文件解析：`lifeline` 3 条（2×256）、`message` 4 条，全部 `startBinding/endBinding` 指向生命线；自调用 4 点正交、返回消息 `strokeStyle=dashed`；标签文本与描述一致。
- Host 集成测试：真实 SDK 工具链 propose → 提案校验 → apply，断言生命线绑定、角色计数与草案/资产不被写入。

## 4.2 类图生成（2026-11-05）

**能力**：`kind=class` 使用 `classes`（2–6 个类，`name` ≤40 字，`attributes`/`methods` 各 ≤8 条、每条 ≤60 字）与 `relations`（≤10 条，可选 `label` ≤14 字）。支持五种关系：`association`、`aggregation`、`composition`、`inheritance`、`dependency`；约定继承 child→parent、组合/聚合 owner→part、依赖 client→supplier。

**布局**：类框为三段式（类名/属性/方法，分隔线 + 分组，拖动整体移动）；2 列或 3 列居中网格，类框宽度按文字预算自适应（200–300px）。关系走既有正交路由器（先不带标签路由，标签单独放在最长段旁并避让类框），不会因 `1..*` 之类的标签导致整图无法布线。

**UML 箭头**：继承 `triangle_outline`（空心三角）、组合 `diamond`（实心菱形）、聚合 `diamond_outline`（空心菱形）、依赖 `arrow` + 虚线、关联无箭头。Excalidraw 原生支持这些箭头形状，无需自绘。

**验证**：生成器测试覆盖确定性、三段框结构、分组、箭头类型与虚线、绑定、标签与画布边界；schema 覆盖混合模型、未知引用、自关联、标签超长与属性超量拒绝；Host 集成测试走真实 SDK 工具链（visualType=uml-class → propose → apply）。真实浏览器视觉验收待补。

## 4.3 画板交互强化（2026-11-05）

飞书的绘图交互更顺手，本轮先补四项可落地的能力（均由 `packages/core/board-interactions.ts` 纯函数实现并测试）：

- **快速连接**：画板主菜单（左上角 ☰）新增「快速连接（C）」或在画布按 C。点击起点形状、再点击目标形状即可自动生成绑定连线（8px 间隙、正交折线、固定点绑定），无需精确拖拽端点；分组素材会解析到绑定壳。直线仍不能作为端点，提示会说明。
- **一键便签**：主菜单「插入便签（N）」或按 N，在视口中心插入 200×132 琥珀色便签（矩形 + 居中文字，组内可整体拖动），双击文字即可编辑。
- **头部保持安静**（按用户反馈迭代）：右上角只保留「返回正文」与主按钮「插入正文草稿」；运行状态移到底部状态栏，工具入口收进主菜单，避免按钮堆叠。
- **对齐与分布**：选中 ≥2 个对象时出现工具条（左/水平居中/右/上/垂直居中/下，水平分布/垂直分布）。分组对象按“整体单元”移动，组内相对布局不被压平；绑定箭头会按固定点重新计算端点，保持连接。
- **对象吸附默认开启**：`objectsSnapModeEnabled` 默认 true，拖拽时与相邻对象自动对齐参考（Excalidraw 原生能力）。

**验证**：新增 `board-interactions.test.ts`（4 项：目标命中与组解析、快速连接几何、组感知对齐 + 箭头重排、分布）；对齐实现过程中修正了“组内成员被拆到同一边”的真实缺陷。扩展类型检查与构建通过；浏览器冒烟因扩展被并行会话反复重载未完成，需补验。

## 4.4 ER 图生成（2026-11-05）

**能力**：`kind=er` 使用 `entities`（2–6 个实体，`name` ≤40 字，`fields` 1–10 条：`name`/可选 `type`/可选 `pk`）与 `entityRelations`（≤10 条，`one-one`/`one-many`/`many-many`，可选 `label` ≤14 字），替代 `nodes/edges`。

**布局与基数**：实体框为「实体名 + 字段列表」两段式，PK 字段自动加 `PK · ` 前缀；网格居中布局，复用正交路由器（先不带标签，标签独立避让实体框）。基数用 Excalidraw 原生 crowfoot 箭头：`one-one` 两端 `crowfoot_one`、`one-many` 起点 `crowfoot_one` 终点 `crowfoot_many`、`many-many` 两端 `crowfoot_many`。

**验证**：生成器测试覆盖确定性、实体/字段结构、PK 前缀、crowfoot 映射、绑定、标签与画布边界；schema 覆盖混合模型、缺字段、未知引用、自关联与标签超长拒绝；Host 集成测试走真实 SDK 工具链（visualType=er → propose → apply）。

**真实 AI 尝试暴露并修复的两个问题（2026-11-05）**：

1. **路由失败导致整图失败**：模型提交的合法 ER 草案在正交布线阶段反复抛出 `BOARD_LAYOUT_TOO_DENSE`，画板没有任何可审阅结果。现类图/ER 均改为「先正交布线（多组方向与间距），全部失败则使用直连回退」：直连箭头从相向边中点出发并绑定固定点，`elbowed=false`；摘要中带 `fallbackRouting:true` 标记。可读的直连图优于失败。
2. **斜线被误判压住标题**：`checkBoardCanvas` 复用了路由器的保守 `segmentHitsBox`，该函数对任意斜线直接返回 true（路由阶段禁止斜线，因此安全），但直连回退产生斜线后，所有斜线箭头都被报 `BOARD_TITLE_OVERLAP`。已新增正确的 Liang–Barsky `segmentIntersectsBox` 用于标题与画幅校验，并补回归测试（标题下方斜线通过、穿过标题的斜线被拦截）。

**长文本布局（已修复）**：实体字段与类属性/方法现在按实际换行结果测量行高（最小 22px），框高与分隔线位置随内容增长；长字段不会压住下一行，类方法区始终从属性区下方开始。新增回归测试覆盖 60 字中文长字段的两个分支。

**头部精简回归修复**：精简头部时误删了 AI 入口，已将其加回画板主菜单（「AI 生成整图 / AI 协作」），与快速连接、便签、补齐素材并列。

## 4.5 工作项引用与预览交互（2026-11-05）

## 4.7 Mermaid 导入（2026-11-05）

画板主菜单新增「导入 Mermaid…」：弹窗粘贴 `flowchart / sequence / class / state / ER` 等 Mermaid 定义，一键转换为**可编辑**图形，插入当前视口中心并选中。

- 转换走 `@excalidraw/mermaid-to-excalidraw` 的 `parseMermaidToExcalidraw`；导入的元素再经 `instantiateElements` 重映射 ID/绑定/分组后入画，与画板既有内容互不干扰。
- **体积零常驻**：mermaid 解析器（约 1.8MB 含依赖）通过动态 `import()` 拆成独立分包，仅在首次点击转换时加载；常规打开画板不下载。
- 语法错误在弹窗内就地提示，不关闭弹窗、不改动画布。
- 附带能力：Excalidraw 原生支持**直接粘贴** Mermaid 文本自动转换（无需走菜单）。

**验收时发现并修复的真实缺陷**：Mermaid 原始元素缺少 seed/version 等运行时字段，直接 updateScene 会令 React 渲染崩溃、整页白屏。修复为转换后先经 `restoreElements`（refreshDimensions + repairBindings）规范化，再实例化入画——与 AI 草案渲染路径一致。

**浏览器实测（独立 board.html?demo 页，2026-11-05）**：
- 错误路径：粘贴非 Mermaid 文本 → 弹窗内提示英文错误（来自 mermaid 本体）、不关弹窗、画布不变。
- 成功路径：粘贴 flowchart（需求评审→通过?→归档/返回分支）→ 首次加载约 1.8MB 分包 → 弹窗关闭、无错误、编辑器存活、导入图形自动选中、画布可继续平移交互；修复前同流程 100% 白屏，修复后连续通过。
- 另为画板页新增 `?demo` 自举参数：无宿主消息时挂载空场景，画板功能可在 Polarion 工作台之外独立验证。
