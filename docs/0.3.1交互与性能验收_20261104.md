## 性能采样

同一真实文档、194 个标题、3 轮既有会话、1440×900；操作为输入 44 个字符后清空（不发送）、10 次侧栏拖宽、20 次大纲滚轮。使用浏览器 PerformanceObserver 和 CDP Performance 指标，测量整页主线程，包含原生 Polarion、扩展和浏览器本身的开销。原始 JSON 的采样标签误写为 42，执行脚本的实际字符串长度为 44，前后使用相同字符串。

| 指标 | 修改前 | 0.3.1 |
|---|---:|---:|
| Long Task 条目 | 10 | 1（50ms） |
| >50ms 帧间隔 | 4，最大约 117ms | 0 |
| ScriptDuration 增量 | 606ms | 282ms |
| RecalcStyleDuration 增量 | 519ms | 187ms |
| TaskDuration 增量 | 2742ms | 1744ms |

这是单组现场对照，不是基准分位数或长期压力保证。两次拖动结束宽度相差不足 1px；页面垃圾回收时机不同，因此不以 DOM/堆内存总量增减宣称内存泄漏已经排除。输入最后均为空，未向正式会话发送消息、未修改正式需求。

用于定位的合成压力夹具为 600 个标题、80 轮历史：20 次输入触发的旧回答 render 从 1600 次降为 0；20 次拖宽的标题文本读取从 24000 次降为 0，偏好写入从 20 次降为 1。这些是本地 React/DOM 夹具计数，不替代上表的真实浏览器数据。

## 新增能力

### 默认专注编辑与素材库

默认专注编辑已在真实页面验证首次打开、手动退出、关闭后重开。段落与单元格属性表单已验证正常宽度取消、390×480 内部滚动/取消，以及实际应用段前1px、单元格内边距8→9后用撤销恢复原DOM；最终草稿保持clean。内容菜单在390×480已验证滚到最后一项、实际命中目标和Esc回焦，底部不超过228px（编辑区底部236px）。

最终部署后，从390×480“段落”入口真实滚动至属性命令并进入表单通过；字体、表格与插入折叠组的末端控件可达，Esc回到具名触发器。1440×900独立菜单位置正常。实际执行两个隔离工作项之间的打开/关闭/切换，标题、正文与草稿状态对应；该项是正常切换验证，不作为保存中竞态实测。

原生 Excalidraw 右侧库展示 36 项内置素材：流程 8、系统与接口 8、控制逻辑 8、热管理 12。全部 36 项完成结构检查；真实页面分别插入四类代表项，修改文字，移动节点并核对正交连接绑定。

个人素材新增、关闭重开后持久化通过；删除一个内置项后不自动复活，“补齐”只恢复缺失项且个人素材 JSON 不变。实际插入正文、明确保存，独立回读 HTML、源 JSON、PNG 与 manifest；25 个原生对象、3 条绑定连线和修改后文字一致，PNG 为 1600×926，再次从正文打开仍可编辑。900×800 的素材库滚动和插入入口通过。

测试结束后个人测试素材已移除，库恢复为 36 个内置项；恢复原有画板恢复数据与 3050 字符正文，并经服务端独立回读一致。该次保存生成的三个测试附件保留在工作项历史中，恢复后的正文不引用它们。209ms 为一次暖启动操作样本，包含 Ego 开销，不代表冷启动或离线性能。未逐一手动插入全部 36 项，未实际制造多标签同时写库冲突。

### Agent 编辑能力契约

默认规则与中文工具说明明确文字替换、简单着色/加粗、复杂排版、图片与画板的可行路径。详情通过只读 `get_editor_capabilities` 按需获取，默认 context 摘要为 552 字符；节点、marks 和属性由实际 schema 派生，不重复维护另一份 schema。

能力契约区分 schema 属性和 serializer 真正可写字段。审查已纠正：`colwidth=null` 不承诺清除既有宽度；同项目、ready、image 状态的普通对话图片资产可用，不误要求单独绑定草稿。参数无效、草稿版本过期和服务端冲突分别处理，不能同参反复试错、扩大用户选区或绕脚本写正文。

原生显示说明直接引用当前正文与标题默认样式，建议整数pt并保留作者显式样式；HTML回读一致和字体/段距/颜色像素一致分开。最后补入这段契约后，6项能力测试、Host类型检查与构建再次通过，已在空闲状态重启到最终Host。

真实 Claude Code 路径使用本机配置的 `deepseek-flash[1m]` 模型，自动批准模式；这里验证的是 Claude Code harness，不将其表述为 Claude 基础模型的结果。

| 实际请求 | 结果 |

| 将所选段落居中、1.75 倍行距；保持文字、数字、单位及其他段落，只改本地草稿 | 46.93s 完成。一次工具发现、能力查询、rich 读取、rich 更新，共 4 次工具调用；0 工具错误、0 审批弹窗、无 Bash 或外部 MCP 绕道。整份 HTML 仅该段新增两项样式，其他内容逐字节不变；远端未变 |

随后由验收操作者点击保存：服务端完整回读 `text-align:center;line-height:1.75`，原生居中显示正确，页面与正文 iframe 的 timeOrigin 均未改变。**原生行距仍有差异**：21R2 将该 `p` 转换为居中的 `div`，计算行高为 20px，未复现编辑器中的 1.75 倍行距。这不是保存失败，也不是像素一致通过；已写入能力工具的 `nativeDisplay.observedLimit` 和随产品提供的 Agent 说明，要求不反复重写相同值或宣称原生效果完全一致。20px 仅为本次样本，不能推广为所有段落的规则。

最后使用新 rich 基线恢复原段落，再走正常 UI 保存；本地和远端 3050 字符 HTML 与原始内容完全一致，远端哈希恢复，草稿为 clean。两次保存全程未重载页面或 iframe；测试编辑窗已关闭，展开上下文卡片后移除测试选区，Host 无运行中的任务。

补入上述实测限制并完成 6 项能力测试、Host 类型检查与构建后，在空闲状态重启最终 Host，再通过真实界面发送只读能力问题：22.995s，工具发现一次、`rich` 与 `errors` 能力各读一次，0 审批。回答正确引用“存储保留、原生 20px、仅具体样本、不重复重写”的新规则；未读取正文、未修改本地或远端。回答比“简短”要求更长，其建议部分不能代替再次实际页面验证；本项只确认最终运行版本可查询并引用新契约。

这两条实际模型请求验证了本轮路线与能力拒绝行为，不证明任意模型、任意提示都一定遵守。第二条回答中将一个产品限制误归因为用户限制，未造成工具操作或数据变动，仍属于回答措辞可改进项。
