# Polarion 编辑工作台：飞书文档、表格与画板对标规格 v0.3

日期：2026-11-03。状态：依据用户最新指令编写的扩展规格；产品实现仍为 partial。

本规格补充已批准 v0.1 与 v0.2。用户明确要求全面对标飞书文档、飞书表格与飞书画板的编辑能力和使用体验，并确认高级对象的可编辑源文件和阅读预览均存入 Polarion。当前浮窗不能作为最终验收样式，也不能以已有按钮数量表示完成。

## 1. 已确认的产品契约

1. 编辑工作台完整替代相应的 Polarion 原装编辑能力；遗漏功能属于缺口，不能通过要求返回原装编辑器处理来关闭验收项。
2. 用户之前选择 C，允许先推进增强文档表格。后续又明确提出全面对标飞书表格和画板。交付规格因此纳入完整表格和画板能力，不能继续把早期 C 当作最终能力上限。多维表格的完整数据库产品另列核对项，不混同电子表格与文档表格。
3. 用户确认存储方案 A：普通正文和文档表格使用原生富文本；高级表格和画板保存可编辑源文件及阅读预览，两者都属于 Polarion 项目工件。未安装助手可以阅读；安装后继续编辑。
4. Claude Code 原生能力仍保留。原生斜杠命令、用户 Skills、MCP、权限和提问，与文档、表格、画板使用同一会话和草稿体系。Codex 继续保持 gpt-6.1-sol，当前账号调用问题单独处理。
5. 全部对象挂接当前项目、文档、工作项及版本，保留 V 模型追踪关系。业务状态变更继续独立于正文保存。

## 2. 工作台交互

### 2.1 三种布局

- 快速浮窗：悬停预览后点击进入，适合短段落与局部修改；原文定位、选区和滚动位置保留。
- 并排工作台：正文或当前对象占主要宽度，右侧 AI 与大纲共用固定工作区；支持固定大纲。
- 专注工作台：大表格和画板可展开，AI 可收为窄栏；退出恢复之前的布局、对象位置与缩放。

模式切换不丢失草稿、撤销栈、选区和会话。一次只激活一个主要对象编辑器；键盘输入和快捷键归属可见编辑区域，不能同时触发 Polarion 或另一个编辑器。

### 2.2 操作入口

常用编辑用就近工具完成：文字选区的浮动工具条、段落左侧插入和移动入口、表格行列柄与右键菜单、画板选中对象的属性条。顶部工具条保持稳定分组；不以常驻多行小图标挤占正文。

正文 `/` 插入块与助手 `/` 原生命令按焦点区分。每个图标有名称、快捷键提示和禁用原因。常用颜色提供语义色板，自定义颜色可用；不能只能在几种预设色中选择。

AI 收到的是所选文字、单元格区域、图形对象及所属版本。用户能看到上下文来自哪里、是否固定、将修改哪一项。选区变化不自动发送，也不能改写正在运行任务的目标。

### 2.3 阅读与视觉

标题、正文、列表、表格、图注、提示块有统一层级。字号、行距、段距、列宽、单元格内边距、背景与边框形成一套一致样式。正文以易读的深灰蓝为主，强调色有含义，错误/警告/普通提示可辨认。

长表格和画板有独立缩放、滚动和适应宽度，不强行缩到不可读。混合内容使用真实 SWR 验收，不用空白页或少量演示文本代表阅读质量。编辑视图、阅读预览和原生 Polarion 页面分别验收。

## 4. 已确认的 Polarion 存储方案 A

每个高级对象具有稳定 objectId、对象类型、所属项目/文档/工作项、编辑器格式版本、源版本与预览版本。源文件、预览及对象清单记录三者的校验值；不要依赖本机缓存作为唯一可编辑来源。

保存顺序：本地草稿 → 检查 Polarion 基线 → 保存本次不可变源附件和预览附件 → 回读字节 → 更新正文中的对象引用与阅读内容 → 独立回读正文及附件 → 标记整次保存完成。

普通表格仍保存成原生 HTML。高级表格保存结构化工作簿，正文包含可读区域或预览和明确的展开入口。画板保存图形源文件及阅读图。原始文件留在 Polarion；不要求另建业务存储服务才能找回源内容。

附件和正文不是原子事务。附件成功而正文失败时保留准确的部分结果，不能把它显示为全部保存成功，也不能盲目重复上传。是否清理未引用附件需依据保存记录判断，不删除其他业务附件。

重要兼容点：实测 Polarion 原生 LiveDoc 会处理标题标签和自定义属性。因此高级对象身份不能只依赖一个自定义 DOM 属性。需要验证正文引用、附件清单和源版本在原生编辑、复制、文档导出、工作项移动后的一致性；找不到源文件时保留预览并明确显示缺失，禁止新建空对象覆盖。

## 6. 场景验收与性能目标

| 场景 | 验收动作 | 通过标准 |
|---|---|---|
| U01 编写一条完整需求 | 标题、正文、编号、提示块、表格、图片、附件、工作项引用 | 全过程在工作台完成，常用动作可发现，无需返回原生补操作 |
| U02 整理接口矩阵 | Excel 粘贴、调整列、合并、批量样式、校验、筛选与公式 | 数值和单位准确，撤销/重做一致，保存后仍可继续编辑 |
| U03 绘制控制流程 | 创建分区/节点/判断/连接/说明，移动与自动布局 | 连线绑定正确，重新打开可编辑，原页面能阅读 |
| U04 人与 AI 协作 | 选一段/一区域/几个节点让 AI 修改，再手工调整 | AI 目标准确，变更可审阅，版本冲突不覆盖 |
| U05 异常恢复 | 关闭浮窗、刷新页、重启 Host、断网或写入响应丢失 | 草稿与保存结果可判断，不产生虚假的“已完成” |
| U06 阅读与复用 | 无插件阅读、安装助手继续编辑、导出、原生再编辑 | 可读与可编辑来源一致，缺失信息明确，工程追踪保留 |

性能目标待实测：已载入工作项输入响应 P95 ≤ 50 ms；缓存对象打开到可编辑 ≤ 500 ms；常用菜单反馈 ≤ 100 ms。压力样本至少包括真实 79 KB 复杂 HTML、1000×20 单元格矩阵及 300 节点/500 连接画板。冷启动、网络与模型耗时分开记录；超预算需定位，不能用小样本结果代表大文档表现。

任何验收项需要功能结果、交互记录、保存回读及适用的性能证据。没有实际运行证据统一标为未验证。37 项现有自动检查不覆盖这份新增的完整验收范围。

## 9. 悬浮工作台内的人与 AI 协作补充（用户 2026-11-03 确认）

悬浮富文本不是独立工具：正文、表格、图片及展开画板均需在同一编辑工作台内与 AI 并排协作。复用主侧栏的项目会话、原生引擎、Skills、MCP、附件、权限与历史，不能维护第二套脱节的聊天记录。

- 普通与专注模式均提供可收起的 AI 面板；画板展开后保留同一面板，工具内也有 AI 展开/收起入口。关闭编辑工作台恢复原有大纲/属性位置。
- 文字、表格选区和图片引用自动进入上下文；画板选区包括对象 ID、文字、位置与连接信息。自动捕获不等于自动发送。
- 发起 AI 任务前同步当前手工正文。AI 对共享草稿的更新可回到当前编辑面；存在未同步人工输入时不得自动替换。远程保存始终是明确操作。
- 画板 AI 结构化读写、变更预览、对象级冲突，以及工作簿区域/公式协作仍需接入和验收。当前“画板选区进入对话”不等于这些工具已全部实现。
