# S1 能力验证报告

日期：2026-11-03，Asia/Shanghai。基准：已批准的功能规格 v0.1。总体状态：**partial**，不能视为完整产品或 S1 全项验收通过。

## 已得到的关键结论

1. ego 0.6.2.5 可以安装本次 Manifest V3 探针，并能通过标准 Native Messaging 调用当前用户的本地宿主。独立开发空间 ID 为 2。
2. Polarion 21 R2 的实际 SOAP 接口支持本项目需要的多种文档结构操作。已用隔离文档完成创建、章节、父子层级、顺序调整、段间正文更新，以及“从文档移除但保留工作项”的写入和回读。
3. 普通 Tiptap 配置无法保留 Polarion 宏及原始样式；自定义内容映射是必需工作。已有源文本保真基础模块，不是完整富文本编辑器。
4. Claude Code 的两轮对话与跨进程会话恢复通过。Codex app-server 协议启动正常，但实际模型调用被当前账号拒绝；原生 `codex exec` 同样失败，不能归因于侧栏界面。
5. 已确认当前 Codex CLI 的配置就是 `gpt-6.1-sol`，无 profile 覆盖，TOML 语法有效。用户再次明确要求该值后未做多余改写；测试其它模型只使用会话级参数。

## G03：富文本保真与字符兼容

对正式示例文档及两个工作项进行了只读采样，未向正式项目写入。样本分别约 317 KB、80 KB、127 B。它们仅保存在被版本控制忽略的本机 `*-private.json` 文件中，没有复制真实需求正文到沙箱项目。

`LosslessHtml` 通过解析位置定位修改，未修改部分沿用原始源文本。类型检查和 **12 项底层测试**通过，覆盖原文不变、单表格单元格修改、实体、中文、非 BMP 字符、过期定位、重叠修改、未知宏保护、完整块移动及无效控制字符。

对照测试中，普通 Tiptap StarterKit 序列化丢失了 Polarion 宏 ID 和样式。因此后续必须提供自定义节点与映射，不能把 `editor.getHTML()` 直接作为保存载荷。

沙箱使用合成的合并单元格、嵌套表格、未知宏、样式及图片引用做写回。表格结构、宏身份、附件引用均保留，但直接传入的 emoji `🚙` 被写回链路移除。改用 `&#x1F699;` 和数学字符的 `&#x1D6FC;` 后，合成样本按原字符串回读成功，测试工作项随后恢复原正文。新文字片段编码现使用该已验证的表示方式；这是特定实例与样本的证据，不代表所有公式、宏和附件都已覆盖。

性能采样是 Node 进程中的 50 次解析，不是浏览器完整编辑性能验收。尚未验证完整 Tiptap 交互、公式编辑、所有图片归属与版本、大表格编辑、粘贴和导出。

证据：`core-checks.json`、`richtext-probe.json`、`unicode-roundtrip.json`。

## G06：原生未保存内容

在隔离文档中输入临时标记时，DOM 文本先发生变化，原生保存按钮随后才变为启用。自动化撤销操作中还观察到按钮已禁用而 DOM 临时文字仍存在。不能单独依赖按钮 class 判定“安全可写”。此现象仍需结合原生事件、输入法和人工键盘操作进一步核验，不直接判定为 Polarion 产品缺陷。

本轮没有点击原生保存；重新加载后临时标记消失、正文恢复、保存按钮禁用。后续必须同时跟踪输入事件、源快照、页面状态和服务器版本。多标签冲突与跨窗口编辑尚未验证。

还发现原生 UI 会把纯标题渲染成 `id=1|new=1` 的临时宏。它不是已持久化的工作项身份，现有探针已避免把该临时 ID 当正式工作项 ID。

证据：`native-dirty.json`、`native-clean-after-reload.json`。
